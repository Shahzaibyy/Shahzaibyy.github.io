🪆 The Envoy Matryoshka Doll Mental Model

How Envoy configurations and request processing are nested from L4 entry down to Pod instances. Each outer layer decapsulates and hands off to the inner layer.

INCOMING REQUEST curl https://api.example.com/v1/checkout ➡️ Downstream TCP handshake hits the proxy
🪆 Doll 1: Listener (L4 Entry) LDS
What it does: Binds to IP & port (e.g. 0.0.0.0:443). Manages OS sockets, connection pooling, listener filters (TLS Inspector, Proxy Protocol).
🪆 Doll 2: Filter Chain & Downstream TLS SDS / LDS
What it does: Matches SNI (*.example.com) & transport protocol. Terminates TLS using certificates (SDS) and negotiates ALPN (h2, http/1.1).
🪆 Doll 3: HTTP Connection Manager (HCM Network Filter) HCM
What it does: Translates raw byte streams into L7 HTTP requests. Executes HTTP filter chain (Auth, Rate Limiting, CORS, Tracing, Logging) before routing.
🪆 Doll 4: Route Configuration & Virtual Hosts RDS
What it does: Dispatches based on HTTP :authority / Host header. Maps to Virtual Host: domains: ["api.example.com"].
🪆 Doll 5: Route Entry (Path & Header Matcher) RDS
What it does: Matches path prefix (/v1/checkout), headers, or query params. Applies timeout, retries, prefix-rewrite, and selects target cluster checkout_service.
🪆 Doll 6: Cluster (Upstream Service Definition) CDS
What it does: Defines the upstream backend pool. Handles Load Balancing (Round Robin, Least Request), Circuit Breakers, Health Checks, Upstream TLS.
🌰 Core Seed: Endpoints (Upstream Pod Instances) EDS
The Destination: The actual backend network addresses: 10.244.1.42:8080 (Healthy), 10.244.2.18:8080 (Healthy), 10.244.3.99:8080 (Healthy).

💡 Why the Matryoshka Metaphor?

In Envoy, configuration isn't flat. Every request undergoes gradual unwrapping:

  • Doll 1: Unwraps TCP connection
  • Doll 2: Unwraps TLS crypto
  • Doll 3: Unwraps HTTP stream
  • Doll 4: Identifies domain
  • Doll 5: Identifies route
  • Doll 6: Identifies pool & policy
  • Core Seed: Hands off to the target pod

⚡ xDS Dynamic Updates

Because of this nested structure, Envoy decouples lifecycles via xDS:

  • EDS (Pod churn): Updates in ms, doesn't touch routes.
  • RDS (Routes): Updated on ingress reload, doesn't bounce listener.
  • LDS (Ports): Set once, rarely reloaded.
